[[ ЧТО УМЕЕТ ИНТЕРФЕЙС ]]

Платформа обслуживает три категории пользователей: студент, преподаватель и администратор.
У каждого свой личный кабинет, свои экраны и свои права доступа.

Помимо этого — безопасный вход и интерфейс, который одинаково удобно работает на компьютере и планшете.

---

[[ ПОЧЕМУ ОДНОСТРАНИЧНОЕ ПРИЛОЖЕНИЕ ]]

Чтобы всё это работало быстро и отзывчиво, интерфейс построен как одностраничное приложение.
В обычных сайтах каждый переход по ссылке — это полная перезагрузка: сервер каждый раз заново формирует страницу и отправляет её целиком.

При первом заходе один раз скачивается код всего интерфейса, и после этого все переходы между разделами происходят мгновенно — как в мобильном приложении.
Сервер отдаёт только данные, не пересобирая страницу заново.
Для платформы, где пользователь постоянно переключается между уроками, заданиями и аналитикой, это принципиально важно.

Если говорить коротко: интерфейс — это одностраничное приложение, которое работает как конструктор: собирается из готовых блоков, загружает только нужное и защищает каждый раздел в зависимости от роли пользователя.

---

[[ ТЕХНОЛОГИИ ]]

Теперь об инструментах, на которых всё построено.

[[ React ]]
Основа интерфейса — React, широко применяемый инструмент для построения интерфейсов.
Главная идея простая: интерфейс собирается из готовых блоков, как конструктор.
Кнопка, карточка курса, форма входа — каждый блок написан один раз и используется в любом месте приложения.
Рассматривались и другие инструменты, но React выбран за наибольшее количество готовых решений и проверенную гибкость.

[[ TypeScript ]]
Код написан на TypeScript — это расширение обычного языка веб-разработки с дополнительной системой проверки.
Она работает ещё до запуска приложения: если где-то данные не совпадают — например, сервер прислал не то, что ожидал интерфейс, — система сразу указывает на проблему.
Это работает как проверка орфографии в Word: не ждёт, пока читатель споткнётся, а подчёркивает ошибку сразу.
При каждой сборке эта проверка запускается автоматически — проблемы выявляются до того, как они доходят до пользователя.

[[ Vite ]]
За сборку готового приложения отвечает Vite.
Он удаляет неиспользуемый код, сжимает файлы и разбивает приложение на части — чтобы загружать только то, что нужно пользователю прямо сейчас.
В разработке он же ускоряет работу: любое изменение в коде отражается в браузере мгновенно.

[[ TailwindCSS ]]
Для визуального оформления используется TailwindCSS.
Итоговый файл со стилями содержит только то, что реально используется на страницах — всё лишнее автоматически удаляется при сборке.

[[ React Router ]]
Переходы между страницами управляются через React Router.
Он поддерживает вложенные разделы, адреса с параметрами — например, с идентификатором конкретного курса —
и защищённые страницы: если пользователь не авторизован или у него нет нужных прав, он автоматически перенаправляется.

[[ Framer Motion, Lucide, Prism ]]
Из дополнительных инструментов: Framer Motion отвечает за плавные анимации при переходах между экранами,
Lucide — набор векторных иконок, используемых по всему интерфейсу,
Prism — подсвечивает синтаксис кода прямо в уроках по программированию, чтобы студенту было удобно читать примеры.

[[ СТРУКТУРА КОДА ]]

Всего в проекте 22 экрана: кабинеты всех трёх ролей, прохождение курса, аналитика, настройки и служебные экраны.

Код разделён на чёткие слои — страницы, компоненты, авторизация, работа с сервером и общее хранилище данных.
Каждый слой отвечает за своё, и при изменении одного остальные практически не затрагиваются.

---

[[ БЕЗОПАСНОСТЬ ]]

Отдельно остановлюсь на безопасности.
Все закрытые страницы защищены специальным компонентом-охранником.
Он проверяет два условия: вошёл ли пользователь в систему, и достаточно ли у него прав.
Например, страница администратора недоступна студенту, даже если он попробует зайти по прямой ссылке.

После входа система выдаёт пользователю два «пропуска».
Первый — краткосрочный, на 15 минут: он подтверждает каждое обращение к серверу.
Второй — долгосрочный, на 30 дней: когда первый истекает, он тихо выдаёт новый.
Пользователь не замечает этого и не выходит из системы принудительно.

[[ ТЕСТИРОВАНИЕ ]]

Тестирование выполнено ручное, по всему проекту.
Прогонялись все ключевые сценарии.

Авторизация: регистрация, подтверждение почты, вход, выход, восстановление пароля.
Студенческий поток: каталог курсов, запись, прохождение урока — теория, тест, задание по коду, — прогресс, обратная связь.
Преподавательский поток: создание курса, добавление материалов, публикация, аналитика по студентам.
Административный поток: управление пользователями и ролями, сводная аналитика.
Двухфакторная аутентификация: включение, вход с кодом, отключение.

Дополнительно: переключение темы, адаптация к разным размерам экрана, уведомления, поведение при ошибках сети.

Все сценарии проходят успешно.

## Вероятные вопросы и короткие ответы

**«Почему не взяли готовую платформу, например Moodle?»**
Готовые платформы плохо поддаются кастомизации — под задачу с тремя ролями, AI-обратной связью и специфической аналитикой проще строить с нуля, чем ломать чужую архитектуру.

**«Чем ваш интерфейс отличается от, например, Coursera?»**
Интеграция AI-обратной связи прямо в поток прохождения урока, не как отдельный инструмент. И закрытая экосистема, в которой преподаватель сам создаёт и публикует курсы без модерации.

**«Проводилось ли автоматическое тестирование?»**
Автоматические тесты — следующий шаг развития проекта. На текущем этапе объём сценариев позволял покрыть всё ручным тестированием, приоритет был отдан полному покрытию, а не автоматизации.

**«Как приложение ведёт себя при медленном интернете?»**
Благодаря разбиению на части каждый раздел подгружается отдельно. Пользователь видит загрузку только для нужного раздела, остальной интерфейс остаётся рабочим.
